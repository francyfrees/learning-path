# 全栈工程路线

一份写给自己的全栈路线图。

不是课程清单，是**验收表**——每一层都回答「学到什么程度算过关」，而不是「看完了哪些视频」。

## 怎么用这份路线

- **以交付物验收。** 看完教程不算过关，能独立做出那件东西才算。
- **不按顺序走。** 遇到问题就跳着补，补齐了再回来。路线是地图，不是轨道。
- **只收录真用过的链接。** 收藏夹里的东西不写进来，写进来的都是从里面爬出来过的。

## 能力地图

| 层 | 要回答的问题 | 过关标志 |
|---|---|---|
| L0 计算机基础 | 请求从浏览器发出到回来，中间发生了什么？ | 能独立定位一次线上慢请求 |
| L1 前端语言 | 这段代码为什么这样跑？ | 不看文档写出符合规范的表单 |
| L2 框架与工程化 | 为什么用它，不用会怎样？ | 能画出首屏每个请求的来龙去脉 |
| L3 服务端 | 接口怎么设计才不容易被用坏？ | 从零写出带权限模型的 CRUD |
| L4 数据与中间件 | 这条查询为什么慢？ | 把 800ms 的查询压到 20ms 并解释原因 |
| L5 交付与运维 | 怎么让它稳定地跑在服务器上？ | 一条命令部署，并能回滚 |
| L6 系统设计 | 用户量翻十倍，哪里先崩？ | 画出架构图并指出瓶颈 |

## L0 · 计算机基础

贯穿全程，不需要先学完再动手。

- **网络**：TCP/IP、HTTP/1.1 与 HTTP/2 的差异、TLS 握手、DNS 解析链路、CDN 回源
- **操作系统**：进程与线程、文件描述符、内存与页缓存、I/O 模型
- **数据结构与算法**：数组 / 链表 / 哈希 / 树 / 堆，排序与二分，复杂度直觉
- **编码**：字符集与编码、Unicode 与 UTF-8、Base64

> 过关：能用 `curl -v` + `tcpdump` + 服务端日志，说清一次「接口慢」到底慢在哪一跳。

## L1 · 浏览器与前端语言

- **HTML / CSS**：盒模型、层叠与优先级、Flex / Grid、响应式、可访问性
- **JavaScript**：事件循环与微任务、原型链、闭包、`this`、异步模型
- **TypeScript**：泛型、类型收窄、条件类型、声明合并、类型体操的边界
- **浏览器**：渲染管线（解析 → 布局 → 绘制 → 合成）、重排与重绘、事件委托

> 过关：不查文档写出一个键盘可操作、有语义标签、支持深色模式的表单。

## L2 · 框架与工程化

- **React**：渲染模型、Hooks 的规则与依赖、并发特性、Server Components
- **Vue**：响应式原理、编译期优化、`keep-alive` 的缓存机制
- **构建**：Vite / Webpack，模块解析、tree-shaking、代码分割、产物分析
- **状态与数据层**：客户端缓存与失效策略、乐观更新、类型安全的 RPC
- **性能**：Core Web Vitals、资源优先级、懒加载、图片与字体

> 过关：打开 DevTools，能说清首屏每一个请求是谁发的、为什么是这个顺序。

## L3 · 服务端

- **Node 运行时**：事件循环各阶段、Buffer 与 Stream、`worker_threads`、内存泄漏排查
- **API 设计**：REST 与 RPC 的取舍、错误契约、幂等、版本化、分页策略
- **认证授权**：Session / JWT、密码存储、RBAC、越权的三种典型形态
- **校验与契约**：schema 校验、端到端类型推导、防止「前端传什么就信什么」

> 过关：从零写一个带角色权限、软删除、并发安全的 CRUD 服务。

## L4 · 数据与中间件

- **PostgreSQL**：BTree / GIN 索引、执行计划、事务隔离级别、MVCC、锁
- **ORM**：schema 设计、迁移管理、N+1 与预加载
- **Redis**：缓存策略、过期与淘汰、分布式锁、缓存穿透 / 击穿 / 雪崩
- **消息队列**：重试与退避、幂等消费、死信处理
- **一致性**：事务边界、最终一致、补偿

> 过关：把一条 800ms 的查询优化到 20ms，并且能解释清楚每一步为什么有效。

## L5 · 交付与运维

- **Linux**：常用命令、systemd、日志与进程排查、权限
- **Docker**：镜像分层、多阶段构建、构建缓存、Compose 编排
- **CI/CD**：流水线设计、测试门禁、制品管理、失败即停
- **Nginx**：反向代理、路径重写、gzip 与缓存头、HTTPS
- **可观测性**：结构化日志、指标、链路追踪、告警阈值

> 过关：一条命令把项目部署到服务器，出问题能一条命令回滚。

## L6 · 系统设计

- **拆分**：什么时候该拆服务，什么时候不该
- **扩展**：读写分离、分片、无状态化、水平扩容
- **实时**：SSE / WebSocket / 轮询的取舍与成本
- **稳定性**：限流、熔断、降级、超时预算

> 过关：画出支撑一万在线的架构图，并指出第一个会崩的地方。
